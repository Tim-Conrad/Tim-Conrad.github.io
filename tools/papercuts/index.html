Why I built it

Small things get in the way all day. A button overlaps on the phone. A tool prints output that my agent cannot use. A rule in a project file points to a file that moved. Each one costs a few minutes, and the next session pays them again.

I had built the same fix three times: a note tab on my pen-and-paper review site, a note tab on the review copy of this site, and a log where agents wrote down what slowed them down. Each kept its notes in its own place and its own shape.

Papercuts puts them together. I report on the page, my agent reports from the terminal or from the browser, and every report becomes a GitHub issue in the same format. The agent that picks up the work reads all of them the same way, and fixes them one by one.

It runs only on my local sites, behind my login. Visitors of a public site never see it.

The README of the latest release goes here when the site is published. Until then, read it on GitHub.
